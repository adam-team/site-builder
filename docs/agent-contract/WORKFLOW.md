# Контракт агента: от первого вопроса до сайта в интернете

Один порядок для Claude Code и Codex. ⏸ значит стоп: агент задал вопрос и ждёт ответа ученицы, сам дальше не идёт.
Каждый этап заканчивается **файлом** в `projects/<id>/`. Если агент только сказал в чате «я запомнил», этап не закрыт.

Папку проекта агент создаёт один раз: `bash scripts/new-project.sh <id>`. id пишется латиницей, цифрами и дефисами, например `anna-psy`.

## Общие правила

- Задавай один вопрос за раз. К вопросу дай 2-5 вариантов ответа и пункт «свой вариант». Анкету целиком не присылай.
- После ответа делай сводку: «Поняла так: … Верно?». Если верно, запиши в файл этапа. Если нет, переспроси.
- Где выбирают глазами, показывай, а не описывай. Для структуры открой `structure/index.html`, для дизайна `gallery/index.html`.
- Не выдумывай цены, имена, номера, отзывы и цифры. Если данных нет, спроси или поставь `ЗАПОЛНИТЬ`.
- Ключи, пароли и токены ученица вводит сама. Агент не печатает их в чат и не коммитит (см. `SECURITY.md`).
- Если решение отличается от шаблона, запиши его одной строкой в `DECISIONS.md` вместе с причиной.
- Ученица сама ничего не ставит. Python, Node и Chrome проверяет и ставит агент (`SETUP.md`).

## Этап 0. Модель и окружение

Claude Code: самая новая Opus, усилие не ниже high. Codex: самая сильная модель, усилие xhigh. Если модель слабее, скажи об этом сразу.
Окружение: `bash scripts/bootstrap.sh`. Ученице напиши одну строку: «Всё готово, начинаем».

## Этап 1. Тема и цель ⏸ → `BRIEF.md`

Вопросы по одному, варианты в `QUESTIONS.md`, блок A:

1. Как тебя зовут и для кого сайт: для себя или для клиента.
2. **Какая тема?** Чем занимаешься ты или клиент, что продаёшь. Варианты: 10 тем из `python3 scripts/structure.py list`.
3. Кто посетитель сайта и что у него болит.
4. Какое одно главное действие должен сделать посетитель: записаться, купить, написать в WhatsApp, оставить заявку.
5. На каком языке сайт: русский, казахский, английский, два языка.
6. Есть ли сайты-примеры, которые нравятся (ссылки). Если нет, это нормально.

Этап закрыт, когда заполнен `projects/<id>/BRIEF.md`.

## Этап 2. Структура ⏸ → `STRUCTURE.md` и `blocks` в `site.json`

**Сначала спроси:** «У тебя уже есть структура сайта: список блоков, план, документ, пример?»

**А. Структура есть.** Ученица присылает текст, файл или ссылку. Агент:
1. раскладывает её по блокам из `structure/presets.json` (`hero`, `about`, `services` …); если блока нет в списке, ближайший блок плюс строка в `DECISIONS.md`;
2. показывает результат нумерованным списком и спрашивает «Так?»;
3. записывает: сохраняет план в `projects/<id>/structure.json` и запускает `python3 scripts/structure.py write projects/<id> projects/<id>/structure.json`.

**Б. Структуры нет: собираем вместе.**
1. Открой конструктор: `open structure/index.html` (на Windows `start structure/index.html`). Скажи: «Выбери тему, размер и галочками блоки.
   Справа видно, как это будет на телефоне. Потом нажми "Скопировать для агента" и пришли мне».
2. Если ученица не хочет открывать конструктор, проведи её в чате:
   - `python3 scripts/structure.py preset <тема>` даст готовый порядок блоков. Покажи его списком и спроси, что убрать и что добавить;
   - размер: мини (5-6 блоков), полный лендинг (9-12), сайт-визитка (4 страницы). Совет: начинать с одной страницы;
   - для каждого блока одна строка «зачем» из `presets.json`, чтобы ученица понимала, что выбирает.
3. Когда текст пришёл, запиши его в `structure.json` и выполни `python3 scripts/structure.py write projects/<id> projects/<id>/structure.json`.

Этап закрыт, когда `STRUCTURE.md` содержит таблицу блоков по порядку, а `site.json` содержит `preset` и `blocks`.

## Этап 3. Дизайн ⏸ → `DESIGN.md` и `design` в `site.json`

1. Открой галерею: `open gallery/index.html`. Скажи ученице:
   «Это Дизайн-тека: 89 дизайнов в виде видео, как на YouTube. Наведи на обложку, чтобы посмотреть превью, нажми, чтобы открыть видео и живой сайт.
   Вкладки: Мои дизайны (Куралай: BOSS VISION, PERSONA, лендинги), Дизайны платформ, Тренды 2026, GitHub-шаблоны. Выбери до трёх и нажми "Скопировать для агента"».
2. Если ученица сразу называет направление («тёмный», «нежный», «премиум», «как у Apple»), предложи 3 номера: `python3 scripts/catalog.py find <слово>`.
   Пришли ссылки на видео (`gallery/index.html#<номер>`) и картинки обложек (`gallery/media/<номер>.jpg` абсолютным путём в Markdown).
3. Когда ученица прислала номера, по каждому выполни `python3 scripts/catalog.py <номер>`: там видно тип дизайна и как его применять.
   - **tokens** (палитры 9-50). Сайт собирается шаблоном `template/` по структуре этапа 2. Можно поменять цвет, шрифт, радиус, вид первого экрана
     (`split`, `center`, `bold`, `bento`), вид карточек (`soft`, `outline`, `glass`, `flat`, `brutal`, `clay`) и анимацию (`rise`, `fade`, `zoom`, `tilt`).
   - **own** (1-8, дизайны Куралай) и **external** (GitHub). Это готовый сайт: агент копирует его в `projects/<id>/site/` и меняет тексты, цвета, блоки
     под `STRUCTURE.md`. Лицензию шаблона с GitHub сохранить.
   - **fetch** (Cruip). Код не хранится: `bash scripts/fetch-template.sh <номер> projects/<id>/site`.
4. Если выбрано 2-3 дизайна, собери быстрый образец каждого на её структуре (для tokens: `build_site.py projects/<id>` с разным `design`,
   скриншоты в чат) и попроси выбрать один. Можно смешать: «цвета от 45, первый экран от 41» = `tokens` и `layout` в `site.json`.
5. Шрифты: любой из `catalog/fonts.json`. Для казахского языка шрифт обязан содержать `ә ғ қ ң ө ұ ү һ і`, иначе `"lang": "kk"` в `site.json` заменит его сам.
6. Свой дизайн (брендбук, PDF, скриншот, сайт-пример). Возьми из него цвета и шрифты, впиши в `site.json` поле `tokens` поверх ближайшей палитры.

Этап закрыт, когда `DESIGN.md` содержит номер, тип, цвета (hex), шрифты, раскладку и причину выбора, а в `site.json` стоит `design`.

## Этап 4. Тексты и материалы ⏸ → `CONTENT.md` и `content` в `site.json`

Иди по блокам из `STRUCTURE.md` сверху вниз. По каждому блоку один вопрос (блок F в `QUESTIONS.md`):
первый экран (заголовок, подзаголовок, кнопка), о себе, услуги и цены, шаги, цифры, отзывы, вопросы, контакты.

- Можно предложить черновик заголовка и текста, но пометь его `ЧЕРНОВИК` и получи «да».
- Цены, цифры, отзывы, телефоны: только со слов ученицы.
- Фото: ученица кладёт файлы в `projects/<id>/assets/`. Пока фото нет, в шаблоне стоят цветные заглушки.

Поля `content` в `site.json`: `brand, kicker, title, sub, cta, cta2, cta_link, trust[], about_title, about, about_points[], items[{title,text}],
benefits[], steps[], stats[{value,label}], program[], testimonials[{name,text}], prices[{name,price,points[],hot}], team[{name,role}],
faq[{q,a}], cta_title, cta_text, contacts{whatsapp,telegram,instagram,email,address}, gallery[]`.

Этап закрыт, когда `CONTENT.md` заполнен, а `python3 scripts/build_site.py projects/<id>` не печатает строку `ЗАПОЛНИТЬ` (или ученица согласилась оставить образец).

## Этап 5. Сборка → `projects/<id>/site/`

- **tokens:** `python3 scripts/build_site.py projects/<id>`. Фото из `assets/` агент подставляет вместо заглушек `.art` (тег `<img>` внутри блока).
- **own / external / fetch:** копия шаблона в `site/` (для external сохранить `LICENSE`), затем по `STRUCTURE.md` удалить лишние блоки и добавить недостающие
  (их можно взять из `template/` или из `designs/external/mertJF--tailblocks`), тексты из `CONTENT.md`, цвета и шрифты из `DESIGN.md`.
  React и Next-шаблоны собираются: `npm install && npm run build`.
- Правки хирургические (`.claude/skills/karpathy-guidelines`): ничего «заодно», работающее не ломать.

## Этап 6. Проверка ⏸

1. Открой сайт и сделай скриншоты: компьютер (1280) и телефон (390). Покажи ученице.
2. `bash scripts/check-site.sh projects/<id>/site` ищет заглушки, «ЗАПОЛНИТЬ», чужие имена, битые ссылки и номер `77000000000`.
3. `bash scripts/check-secrets.sh` должен показать «чисто».
4. Спроси: «Что поправить?». Правки собери пакетом, потом сделай одну пересборку.

## Этап 7. Запуск ⏸

Перед выкладкой спроси подтверждение. Варианты (блок G):
1. **Vercel**, бесплатно, с адресом `имя.vercel.app` и своим доменом позже: ученица входит в Vercel сама, агент запускает `npx vercel deploy projects/<id>/site --prod`.
2. **GitHub Pages**: отдельный репозиторий ученицы с папкой `site/`.
3. Отдать архив `site.zip` для своего хостинга.

Этап закрыт, когда есть рабочая ссылка, и она записана в `projects/<id>/BRIEF.md`.
